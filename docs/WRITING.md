# 文書の書き方（WRITING.md）

このリポジトリの README・修正一覧・マニュアルなどを書く人（人間も AI も）のための決まりです。**文書を書く・直す前に、必ず全部読んでください。** 新しい版の説明を足すときも、ほかの所を直すときも同じです。

この決まりは、読みにくくなった文書を 2026-10 と 2026-11 に書き直したときのものです。書き直した後に足した文が、また元の読みにくい書き方に戻ったため、ここに書いて残しています。

## 1. いちばん大事なこと

1. **読む人は、このソフトを使う人です。** 開発の経過、テストの手順、内部の仕組みは、使う人が判断に要る結論だけを書きます。
2. **事実と数値は変えない・落とさない。** 版番号、コマンド名、設定名、既定値、ファイル名、倍率、局数、Elo とその幅、ノード数は、そのまま残します。書く場所を移すのはかまいません。
3. **書いてないことを足さない。** 確かめていないことを、確かめたように書かないでください。
4. **確かめたこと・確かめていないことの区別は大事な情報です。** 消さずに、決まった場所に短く書きます（修正一覧の **未確認** と、4 章の検証記録）。

## 2. 文の書き方

- 文は短く。1 文に 1 つの事柄。「〜で、〜し、〜なので、〜」と続けない。
- 1 つの箇条に 1 つの事柄。箇条が 3 行を超えたら分ける。
- かっこの中にかっこを入れない。説明が長くなるなら、別の文か別の箇条にする。
- 手順は番号付きの箇条、条件の列挙は箇条か表にする。
- 要約の文を太字にしない（太字は、読み落とすと困る注意の 1 文だけ）。
- 「上の」「下の」で別の節を指さない。版の名前、節の番号、リンクで指す。
- 日本語は「です・ます」。英語は自然な技術英語（日本語の直訳にしない）。

## 3. 用語

使わない言い方と、代わりに使う言い方です。

| 使わない | 使う |
|---|---|
| 命令（コマンドの意味で） | コマンド（CPU の命令は「命令セット」） |
| 試験 | テスト |
| 組み立て（る）（ビルドの意味で） | ビルド（する） |
| 配布物 | 配布版、または Release の ZIP |
| 道具 | ツール |
| 手引き・説明書 | マニュアル |
| （コマンドを）打つ | 入力する・実行する（オセロの手は「打つ」のまま） |
| 歩く・歩き（book の中を） | たどる |
| 窓 | ウィンドウ（ファイルを選ぶ窓は「ダイアログ」） |
| 裏で・裏の（処理） | バックグラウンドで・バックグラウンドの（画面の文言はそのまま） |
| 系（エンジンの系など） | 系列（画面の文言はそのまま） |
| 写し | コピー |

- 画面の項目名・メッセージ・コマンド名・設定名は、画面やソースの文字のとおりに書きます。上の表で言い換えるのは、説明の文だけです。
- 英語の訳語は、英語版のマニュアルの用語集に合わせます。

## 4. 検証の記録は修正一覧に書かない

テストと実測の記録は、修正一覧（CHANGELOG）とは別のファイル（`docs/validation/`）に書きます。

修正一覧に書かないもの：

- テストの項目数、テストの手順、「〜と同じノード数」「〜と同じ book」などの照合の記録、測り方、ワークフローの run の番号。

修正一覧に書いてよいもの：

- 使う人が判断に要る結論を 1 行。例：「探索の結果は前の版と同じです」（互換性に書く）。
- 強さ（対局の結果の Elo の表）は、使う人に要るので **強さ** として修正一覧に残します。
- 確かめていないことは **未確認** に 1 行で書きます。

## 5. 長い図や表

消さずに、GitHub の折りたたみに入れます。中身は変えません。コードブロックの前後には空行を入れます。

```
<details>
<summary>形の図（15 個）</summary>

（中身）

</details>
```

## 6. 日本語版と英語版

- 日本語版を先に書きます。英語版は、日本語版と同じ事実・同じ構成にします。
- 片方だけに情報を足したり消したりしないでください。

## 7. 書き終えたら確かめること

- [ ] 新しく書いた所に、3 章の「使わない」言い方が残っていない。
- [ ] 数値・コマンド名・リンクを、もとの情報（ソース、実行の結果、前の文）と照らし合わせた。
- [ ] 前の版の説明を、頼まれずに書き換えていない。
- [ ] 見出しの文字を変えていない（リンクの行き先になっている）。
- [ ] 日本語版と英語版で、同じ事実・同じ構成になっている。
- [ ] リンクが切れていない（相対リンクのファイルと、`#` の行き先の見出しがある）。

## 8. このリポジトリの文書

| ファイル | 役割 | 書くこと |
|---|---|---|
| `README.md` | 入口 | 何のソフトか、ダウンロードと最初の使い方、3 つの系列、主な変更、ビルド、ライセンス。版ごとの経過は書かない |
| `RELEASE-NOTES.ja.md`・`RELEASE-NOTES.md` | 修正一覧（日本語が正本） | 版ごとの、使う人に向けた変更。下の形で書く |
| `docs/validation/nikque.ja.md`・`.en.md`、`eval2.ja.md`・`.en.md` | 検証記録 | 版ごとのテストと実測。見出しは修正一覧と同じ `## v4.5.5-…` |
| `manual/ja/`・`manual/en/` | マニュアル | コマンドと設定の使い方。新しいコマンド・設定には「v4.5.5-nikque.N から」と書く |
| GitHub の Release の本文 | その版の要点 | 修正一覧のその版へのリンクを付ける |

- 系列は 3 つあります：nikque（本線）、eval2（nikque に新しい評価関数を足したもの、ブランチ `eval2`）、Heath（旧名 newedax、C++ 版、別のリポジトリ `Nikque/Heath`）。
- eval2 の版で、nikque の版を取り込んだだけのものは、要約に「v4.5.5-nikque.N の変更を取り込みました（`[nikque.N](#v455-nikquen)`）」と書き、eval2 だけのことを足します。同じ説明を繰り返さないでください。
- マニュアルは Heath のリポジトリにもあり、Heath だけの機能（ponder・keep-hash・probcut の既定など）のほかは同じ文です。共通の文を直したら、Heath のマニュアルも同じに直してください。
- マニュアルの冒頭の「対象の版」は、新しい版を出したら直します。

### 修正一覧の 1 つの版の形

見出しの名前はこれだけを使います（「変更点」「直したこと」「確認」「確かめたこと」「試験と測定」などは使わない）。

```
## v4.5.5-xxx.N

1〜2 文の要約。ふつうの文（太字にしない）。その版で使う人に何が変わるか。

**変更**

- 1 つの箇条に 1 つの事柄。新しいコマンドや設定が複数あれば表にする。

**不具合の修正**          ← あるときだけ

- 何が起きていたか → どう直したか。どの版から起きていたか分かれば書く。

**強さ**                  ← 対局の結果があるときだけ。表のまま

**互換性**

- 探索の結果（評価値・ノード数）、`eval.dat`、book のファイル形式、学習でできる book が、前の版と比べて変わるか。

**注意**                  ← あるときだけ（直していないこと、知っておくこと）

**未確認**：……           ← 1 行

[検証記録](docs/validation/<ファイル>.ja.md#v455-xxxn)
```

英語版の見出し：**Changes**、**Fixes**、**Strength**、**Compatibility**、**Notes**、**Not checked**、`[Tests and measurements](docs/validation/<file>.en.md#v455-xxxn)`。

- 版と版の間には `---` を置きます。
- 見出しは `## v4.5.5-xxx.N` だけにします。後ろに文字を足すと、リンクの行き先（`#v455-xxxn`）が変わります。
- 大きな版でも、本文は 35 行くらいまでにします。長くなるときは、検証記録やマニュアルに移せるものを探します。
- 新しい版を足したら、修正一覧の冒頭の「版の対応」の表にも行を足します。
- 見本：前回書き直した版（例：v4.5.5-nikque.22・21・20）。
